# نردبان دوئل: محاسبهٔ برد و کارمزد

## آنچه پیدا شد — و از چیزی که گزارش کردی بزرگ‌تر بود

نردبان دوئل واقعی بود: هر بار «ادامه» می‌زدی، مرحلهٔ بعد با **دو برابر ارزش**
شروع می‌شد و **هیچ بلیط تازه‌ای هم خرج نمی‌شد** — این عمدی و درست است.

اما سرور هر مسابقه را **جدا** تسویه می‌کرد. یعنی سه برد پشت سر هم، سه صندوق
کامل واریز می‌کرد:

| مرحله | ورودی هر طرف | صندوق | آنچه واریز می‌شد |
|---|---|---|---|
| ۱ (سبز) | ۱۲٬۵۰۰ | ۲۵٬۰۰۰ | ۲۳٬۷۵۰ |
| ۲ | ۲۵٬۰۰۰ | ۵۰٬۰۰۰ | ۴۷٬۵۰۰ |
| ۳ | ۵۰٬۰۰۰ | ۱۰۰٬۰۰۰ | ۹۵٬۰۰۰ |
| **جمع** | **یک بلیط ۱۲٬۵۰۰** | | **۱۶۶٬۲۵۰** |

یک بلیط ۱۲٬۵۰۰ تومانی، ۱۶۶٬۲۵۰ تومان پرداخت می‌گرفت. حریف هر مرحله فقط
ورودی خودش را گذاشته بود، پس **مابه‌التفاوت را پلتفرم می‌داد** — روی هر
نردباني که کسی بالا می‌رفت. این نشتی پول بود، نه فقط یک ایراد نمایشی.

## چه شد

حالا **دور** تسویه می‌شود، نه تک‌تک مسابقه‌ها:

- ورود با بلیط، یک **دور** باز می‌کند.
- برد هر مرحله، صندوق را **نگه می‌دارد** — چیزی به کیف پول نمی‌رود.
- «ادامه» همان دور را یک پله بالا می‌برد: ارزش دو برابر، **بدون بلیط تازه**.
  بردِ نگه‌داشته روی مرحلهٔ بعد شرط‌بندی می‌شود.
- «برداشت» **یک بار** پرداخت می‌کند: خالصِ صندوقِ مرحله‌ای که به آن رسیده.
  برای مثال بالا: **۹۵٬۰۰۰ تومان**، یک تراکنش.
- **باخت** در هر مرحله، دور را با صفر می‌بندد. فقط همان **یک بلیط سبز** خرج
  شده و چیزی گرفته نمی‌شود.

## اگر بازیکن بازی را ببندد

اگر مرحله‌ای را ببرد و بدون زدن «ادامه» یا «برداشت» از بازی بیرون برود، بعد
از **۱۰ دقیقه** سرور خودش جایزهٔ آخرین مرحله‌ای که برده به حسابش واریز
می‌کند. پول بازیکن هیچ‌وقت پیش ما نمی‌ماند — و چون باخت همان لحظه دورش را با
صفر می‌بندد، بستن برنامه راهی برای فرار از باخت هم نیست.

## کارمزد در تراکنش‌ها

قبلاً جایزه به این شکل ثبت می‌شد: یک ردیف واریزِ **ناخالص** (۱۰۰٬۰۰۰) و یک
ردیف کارمزد که **از دید بازیکن پنهان** است. نتیجه این بود که در لیست
تراکنش‌ها «۱۰۰٬۰۰۰» نوشته می‌شد ولی ۹۵٬۰۰۰ به کیف پول می‌نشست.

حالا فقط یک ردیف ثبت می‌شود، با **همان مبلغی که واقعاً رسیده**: ۹۵٬۰۰۰.
مبلغ کارمزد روی همان ردیف نگه داشته می‌شود (در `metadata`) تا برای حسابداری
در دسترس باشد.

> **نکتهٔ گزارش‌گیری:** اگر جایی درآمد پلتفرم را از جمعِ ردیف‌های `fee` حساب
> می‌کنی، برای دوئل دیگر چنین ردیفی ساخته نمی‌شود — چون بازیکن اصلاً مبلغ
> ناخالص را دریافت نمی‌کند. کارمزدِ هر پرداخت روی خود ردیف جایزه است
> (`metadata.fee`). اگر بخواهی، گزارش را طوری تنظیم می‌کنم که این را هم
> بخواند.

## دستور انتشار

**هر دو تکه لازم است**؛ اول سرور:

```
sudo tar -xzf /home/ubuntu/pz-dist-contents.tgz -C /home/ubuntu/pz-dist --overwrite
```

```
sudo docker compose -p prizzequizz restart api
```

```
sudo cp /home/ubuntu/prizze-v643.html /var/www/prizequiz/index.html
```

> جدول `duel_runs` خودش موقع بالا آمدن سرور ساخته می‌شود؛ کار دستی روی
> دیتابیس لازم نیست.

## نکته‌ای دربارهٔ دورهای نیمه‌تمام

نسخهٔ قبلی چنین چیزی نداشت، پس دوری که همین حالا وسط بازی است بعد از
راه‌اندازی مجدد، دور شناخته‌شده‌ای ندارد و مثل قبل تسویه می‌شود. برای همین
بهتر است انتشار را در ساعتی انجام دهی که کسی وسط نردبان نیست.
