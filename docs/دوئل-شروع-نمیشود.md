# دوئل شروع نمی‌شود و برمی‌گردد به خانه

## علت

قبل از شروع هر دوئل یک دروازه هست: بازی باید **مطمئن شود حریف واقعاً داخل
اتاق است**. این محافظ لازم است — اگر حریف کرش کرده یا بیرون رفته، نباید با
هیچ‌کس بازی کنی و باید بلیطت برگردد.

اما این «اطمینان» فقط **یک منبع** داشت: پیام `presence` روی **وب‌سوکت**.

روی شبکه‌ای که وب‌سوکت را عبور نمی‌دهد، آن پیام هیچ‌وقت نمی‌رسید. پس دروازه
۱۵ ثانیه صبر می‌کرد و بعد همیشه یک نتیجه داشت: «حریف به بازی متصل نشد» →
بلیط برگشت → صفحهٔ خانه → بازی شروع نشد. هر بار. و چون آخرین بازمانده اصلاً
به وب‌سوکت کاری ندارد، روی همان گوشی و همان اینترنت بی‌مشکل بازی می‌شد.

پیغام «اتصال زنده قطع شد» که می‌دیدی درست بود — واقعاً سوکت وصل نمی‌شد — ولی
مسیر پشتیبان فقط برای **جواب دادن** ساخته شده بود، نه برای **شروع** مسابقه.

## چه شد

**سمت سرور:** حالا سرور می‌داند چه کسی داخل هر مسابقه است، از روی
درخواست‌های معمولی‌ای که هر بازیکن به‌هرحال می‌فرستد — خواندن مسابقه، گرفتن
سؤال‌ها، شروع، جواب دادن. ورود از وب‌سوکت هم در همان جا ثبت می‌شود، پس
بازیکنی که سوکتش کار می‌کند برای حریفی که سوکتش قطع است هم دیده می‌شود.
`GET /matches/:id` حالا `presentUserIds` را برمی‌گرداند.

**سمت بازی:** دروازه دیگر فقط به سوکت گوش نمی‌دهد؛ هم‌زمان از سرور هم
می‌پرسد. هر کدام زودتر جواب داد، همان کافی است.

و یک نکتهٔ ظریف که کار را کامل می‌کند: **خودِ منتظر ماندن، اعلام حضور است** —
چون پرسیدن از سرور یعنی خواندن مسابقه، و خواندن مسابقه یعنی ثبت شدن. برای
همین دو بازیکن که **هر دو** سوکتشان قطع است هم همدیگر را پیدا می‌کنند.

محافظ سر جایش است: حریفی که واقعاً نیامده، در هیچ مسیری دیده نمی‌شود، پس
همچنان «حریف به بازی متصل نشد» می‌گیری و بلیطت برمی‌گردد. سابقهٔ حضور بعد از
۳۰ ثانیه هم منقضی می‌شود تا حضورِ کهنه به حساب نیاید.

**و آن پیغام:** «اتصال زنده قطع شد — بازی از مسیر پشتیبان ادامه دارد» حالا
۴.۵ ثانیه بعد خودش محو می‌شود. یک خبر است، نه ایرادی که بازیکن بتواند کاری
درباره‌اش بکند، و روی شبکه‌ای که هیچ‌وقت سوکت را عبور نمی‌دهد نباید تمام
مسابقه بالای صفحه بماند.

# و اما «سایت روی بعضی گوشی‌ها بالا نمی‌آید»

اینجا باید دو چیز را از هم جدا کنیم، وگرنه دنبال چیزی می‌گردیم که مشکل نیست.

## قدم اول: مطمئن شو نسخهٔ جدید واقعاً روی سرور است

این را روی سرور بزن:

```
curl -s https://prizze.quiz/ | grep -c fonts.googleapis.com
```

- جواب **۰** → نسخهٔ اصلاح‌شده بالاست.
- جواب **۱ یا بیشتر** → هنوز فایل قدیمی سرو می‌شود. آن وقت اصلاً عجیب نیست
  که گوشی‌های تازه باز نمی‌کنند: همان خط فونت گوگل هنوز سرِ جایش است. فایل
  را دوباره کپی کن و همین دستور را دوباره بزن.

نکتهٔ مهم: گوشی‌ای که **قبلاً** سایت را باز کرده، فایل را در کش مرورگرش دارد
و ممکن است هنوز نسخهٔ قدیمی را ببیند. برای تست واقعی روی همان گوشی، یک بار
در حالت **ناشناس/Incognito** باز کن.

## قدم دوم: روی یک گوشیِ خراب، این را باز کن

```
http://193.93.169.245/
```

(همان IP سرور خودت، بدون نام دامنه.)

- **بالا آمد** → شبکهٔ گوشی به سرور می‌رسد. پس مشکل روی **نام دامنه** است:
  DNS گوشی. روی اندروید: تنظیمات → شبکه و اینترنت → **Private DNS** را روی
  Off یا Automatic بگذار و دوباره امتحان کن. خیلی از گوشی‌های ایرانی
  Private DNS (شکن/۴۰۳/…) روشن دارند و بعضی از این سرویس‌ها دامنهٔ `.quiz`
  را جواب نمی‌دهند. این دقیقاً توضیح می‌دهد چرا لپ‌تاپ روی هات‌اسپاتِ همان
  گوشی باز می‌کند (DNS دیگری دارد) و چرا با فیلترشکن درست می‌شود (DNS خودش
  را می‌برد).
- **بالا نیامد** → گوشی اصلاً به سرور نمی‌رسد و موضوع مسیر شبکه است، نه بازی.

هر کدام که بود بگو، تا از همان‌جا جلو برویم. تا وقتی این دو قدم را نزده‌ایم،
حدس زدن فقط وقت می‌برد.

## دستور انتشار

**اول سرور، بعد بازی** — این دور هر دو تکه لازم است: بدون سرور، بازی
`presentUserIds` را نمی‌گیرد و دروازه باز نمی‌شود.

```
sudo tar -xzf /home/ubuntu/pz-dist-contents.tgz -C /home/ubuntu/pz-dist --overwrite
```

```
sudo docker compose -p prizzequizz restart api
```

```
sudo cp /home/ubuntu/prizze-v643.html /var/www/prizequiz/index.html
```
